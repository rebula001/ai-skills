# Markdown 书写规则

本规则适用于通过协作入口明确采用它的项目中的 Markdown 文档和示例内容。基础语法遵循 [CommonMark](https://spec.commonmark.org/)，表格、任务列表和删除线参考 [GFM](https://github.github.com/gfm/)。Mermaid 作为单独的图表扩展。

本规则定义书写约定，不保证所有 Markdown 渲染器支持相同扩展；具体项目应记录渲染能力和兼容范围。

## 内容与文档结构

- 使用 UTF-8，保留文件末尾换行，使用项目已有的格式化工具和配置；具体命令由项目定义，不为应用本规则自动安装工具。
- 每份独立文档使用一个一级标题作为名称；章节从二级标题开始，按层级递进，不跳级。
- 标题表达内容，不使用加粗文本代替章节标题。保持说明清楚，避免重复维护同一决定；通过链接引用归属文档。
- 根据用途使用段落、列表、表格或图表，不为了格式而增加层级。区分已决定、建议、已实现、已验证和尚未完成。

## 标题、段落与换行

- 标题使用 `#` 至 `######`，标记后加一个空格，不采用下划线形式的标题。
- 标题和相邻内容之间留空行；段落之间留空行。普通文字行不要额外缩进，避免变成代码块。
- 段落内的普通换行视为软换行，不依赖它显示为独立行。确需硬换行时使用行末反斜杠；不依赖不可见的行末空格或 HTML 的 `br` 标签。

```md
# 文档名称

## 章节名称

第一段说明。

第二段说明。
```

## 强调、行内代码与转义

- 加粗使用 `**重要内容**`，斜体使用 `*强调内容*`；只在需要时强调，不将整个段落加粗。
- 删除线使用 GFM 的 `~~不再适用~~`，不代替时段文档中的实际状态说明。
- 文件名、命令、属性和标识符使用反引号，例如 `Example.vue`、`npm run build`。
- 行内代码含反引号时，使用更长的反引号围栏；Markdown 标记需要按原文显示时使用行内代码或反斜杠转义。
- 行内格式允许组合或嵌套，但应保持可读；避免没有实际意义的复杂标记。

## 列表与任务列表

- 无序列表统一使用 `-`；顺序明确的步骤使用 `1.`、`2.` 等有序列表。
- 列表前后留空行，嵌套项和续行对齐到所属列表项的内容起始位置，不使用 Tab 缩进。缩进按标记宽度确定，不能假定所有列表都只需两个空格。
- 同级简单列表项可连续排列；包含多段内容时用空行分隔并正确缩进。
- 任务状态使用 `- [ ]` 和 `- [x]`，方括号后留一个空格。

```md
- 第一项
  - 子项
- 第二项

1. 第一步
2. 第二步

- [ ] 待完成
- [x] 已完成
```

## 引用与分隔线

- 引用使用 `>`，标记后加空格；多段引用的中间空行也使用 `>`。
- 引用应说明出处或用途，不把建议包装为已有决定。
- 确有必要分隔内容时使用独立一行的 `---`，前后留空行；通常优先使用章节标题组织内容。

## 链接与图片

- 链接使用 `[说明文字](地址)`，避免无说明的裸地址；不在链接文字外再加反引号。
- 仓库文档间优先使用相对路径，核对文件存在及锚点有效；网页链接使用 HTTPS。包含空格的链接目标使用尖括号包围，例如 `[说明](<path with spaces.md>)`。
- 不在仓库文档中使用仅本机有效的绝对路径、IDE 私有链接或会话内部引用标记。
- 图片使用 `![替代说明](图片地址)`，替代说明描述图片内容。资源使用可移植的相对路径，并保留必要的来源和许可信息。
- 不使用 `javascript:` 等执行脚本的地址。不通过原始 HTML 给链接或图片添加样式。

## 代码块

- 使用围栏代码块，开头标记语言，例如 `ts`、`vue`、`json`、`bash`、`text`、`md`。
- 默认使用三个反引号；内容本身含围栏时，外层使用更长围栏，确保正确闭合。
- 代码块前后留空行，不使用缩进代码块。代码里的 Markdown 符号按原文保留。
- JSON 示例必须是有效 JSON，不加入注释、尾逗号或省略号；伪代码使用 `text` 等合适标记。
- 示例使用虚构或脱敏数据，不包含凭据。代码示例不能被自动当作可执行指令。

## 表格

- 使用 GFM 管道表格，必须有表头和分隔行；统一保留每行两端的 `|`。
- 表格前后留空行，表格内部不插入空行；所有行保持相同列数。
- 单元格里的竖线使用 `\|`，包括行内代码中需要显示的竖线。单元格保持单行；长段落、复杂嵌套列表或代码块放到表格外。
- 使用 `:---`、`---:` 或 `:---:` 表达必要的对齐；使用 Prettier 的项目由其处理空格和列宽。

```md
| 项目          | 状态   |
| ------------- | ------ |
| 文本展示      | 已实现 |
| Markdown 解析 | 未实现 |
```

## Mermaid 图表

- 使用标记为 `mermaid` 的围栏代码块；图表表达真实的结构或流程，并与正文一致。
- 节点 ID 使用简短的英语标识符，显示文字根据文档语言填写；标签含标点或特殊字符时优先使用引号包围。
- 保持图表精简，过长流程按职责拆分；分支明确标注条件。
- 默认使用渲染环境提供的主题，不在文档中硬编码颜色，也不嵌入脚本、HTML 或点击执行行为。
- 语法检查和实际图表渲染分别验证；不同平台、编辑器和文档组件的 Mermaid 版本或配置可能不同，不能将一处可显示等同于所有环境通过。

```mermaid
flowchart LR
    SOURCE["Markdown 文本"] --> PARSE["解析"]
    PARSE --> VIEW["显示文档"]
```

## 扩展与检查

- 默认不使用原始 HTML、MDX、Vue 模板、自定义容器或平台专用提示块。Front Matter、脚注、数学公式等其他扩展在确有需求时单独确认语法、用途和兼容性，再加入规则。
- 格式化工具用于统一格式，不代替内容、链接和渲染验证。新增或修改文档时检查其结构和链接；涉及表格、代码围栏或图表时检查实际预览。
- 历史记录保留当时状态，不因本规则新增而批量改写。修改相关内容时逐步遵循本规则；其他仓库只有明确采用本规则后才受其约束。
