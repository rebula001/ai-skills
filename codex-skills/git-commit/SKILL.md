# Git Commit

## When To Use

当用户要求以下操作时使用：

- 提交当前仓库的改动，或按主题分类提交。
- 提交指定文件、文件夹或子模块相关改动。
- 准备或审阅提交信息；仅要求准备或审阅时不执行提交。

## 确定范围

- “请提交”：当前仓库所有已暂存、未暂存及未跟踪的改动；不主动纳入被忽略的未跟踪文件。已跟踪文件即使后来匹配忽略规则，仍按 Git 状态及用户要求处理。
- “请分类提交”：按改动目的分组；代码、测试和文档尽量放在同一完整提交。检查组间依赖及顺序；无法安全拆分的相关改动说明原因并合理合并，不强行分类。
- 指定文件或文件夹：只处理明确指定的范围；“当前文件”或“当前文件夹”需要可确定的上下文，不明确时询问。
- “请提交子模块”：按下方流程处理目标子模块和主项目指针。若用户明确限定只提交其中一部分，则遵循指定范围。
- 不为整理提交而修改用户内容；不纳入范围外改动，不创建空提交。

## 提交子模块

适用于“请提交子模块”或用户明确要求处理子模块及主项目指针的情形。用户只要求其中一部分时，按指定范围处理。

1. **确定目标**：检查主项目和子模块的分支、暂存区、工作区及远程配置。用户指定子模块时使用该目标；只有一个待处理子模块时可选用；多个候选或目标不明确时询问。detached HEAD 时先告知并核对改动和目标分支，不自动切换、拉取或 cherry-pick。
2. **提交子模块**：检查内部改动并按本 skill 起草英文 Title 和按需提供 Description；展示子模块路径、分支和确切范围，询问是否提交。得到明确确认后提交，保留范围外改动。没有内部改动时不创建空提交。
3. **推送子模块**：提交成功后展示提交号、远程仓库和目标分支，询问是否推送；明确确认后才推送。用户自行推送时先核实结果。推送失败则说明原因并暂停，让用户决定如何继续；用户选择不推送时说明其他人可能无法获取该提交。
4. **提交主项目指针**：回到主项目，检查分支、暂存区和指针是否指向预期提交，为指针变更起草英文 Title 和按需提供 Description；展示范围并询问是否提交。得到明确确认后只提交已批准的指针，不混入其他改动。指针没有变化时不创建空提交。
5. **推送主项目**：主项目提交成功后展示提交号、远程仓库和目标分支，询问是否推送；明确确认后才推送。报告子模块和主项目各自的提交、推送结果及剩余改动。

## Title 和 Description

- **Title（标题）**：每笔提交必须提供，使用英文 Conventional Commits 格式，简短描述改动，例如 `fix(database): preserve row order`。
- **Description（正文）**：根据需要提供英文正文，说明原因、行为或限制；简单改动可以省略。正文有多个适合并列说明的要点时，优先使用列表。
- 正文与标题之间保留一个空行。注意：Conventional Commits 格式中标题冒号后的 `<description>` 是标题的简短描述，不是这里所说的正文。

## 准备和确认

1. 检查当前分支、工作区、暂存区和未跟踪文件；查看实际差异，保留用户已有暂存状态。区分子模块内部状态和指针变化。
2. 为每一组确定文件或改动块、提交顺序及依赖，并读取本地的 [Conventional Commits 1.0.0 规则](references/conventional-commit-guide.md)，按其要求拟定英文提交信息；日常提交不需要访问官网。
3. 展示当前分支、每组范围、未跟踪文件和子模块是否包含在内、每组 Title 和可选 Description（正文；不需要时说明无正文），并说明默认不会推送。普通分类提交请求确认整个方案；子模块按上方步骤分别确认。若无可提交改动，直接说明。
4. 首次“请提交”仅启动流程；只有展示完整方案后的明确确认才执行 `git add` 和 `git commit`。针对该方案的“好”“确认”“ok”“y”等可视为确认；不明确则询问。确认前不改变暂存区。

## 执行和验证

- 执行前重新核对分支、内容和批准范围；若发生影响方案的变化，停止并说明，取得对新方案的确认。
- 按批准顺序逐组处理。每次提交前检查完整暂存区：普通 `git commit` 会提交整个暂存区，不能仅凭刚添加的路径判断范围。若存在不属于本组的已暂存改动，使用能保留其内容和暂存状态的安全方式；无法可靠做到时停止并说明，不擅自重置、覆盖或提交它们。
- 只暂存已批准的路径或改动块；若无法可靠拆分，停止并说明，不擅自扩大范围。每组完成后检查提交和剩余改动。
- 默认只提交当前分支，不自动推送；推送仅在用户明确要求时进行。不得擅自 amend。提交后报告分支、每笔提交及工作区状态；说明失败或未完成事项。
